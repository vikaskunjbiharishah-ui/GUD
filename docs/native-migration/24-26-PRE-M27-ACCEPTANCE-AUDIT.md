## Important security and product decisions

1. Do not weaken native Keystore access to reproduce the original questions-only forgot-password shortcut. The present pre-issued offline recovery code plus device credential protects an already enrolled native verifier more strongly. Human security answers remain verifier material for old backup identity restore. An owner-approved alternative must be threat-modelled before shipping.
2. A `HUF` or `Joint` family record is not proof of two legal beneficial owners of the same custody account. The v4 custody and ledger relations have one accountable owner. A v5 fractional ownership migration must explicitly specify shares, cost basis, corporate actions, income, tax and CAS matching before implementation.
3. Both M25 historical `.kosha` and new native portable backup restore reject nonempty target vaults; no implicit overwrite or merge. A full restore into a different installation requires source account proof and encrypted backup, not a missing old Android Keystore.
4. Missing Tax/Documents UI is **not** evidence those screens were delivered by M26. The shared top-level family selection is available for their later integration but cannot be accepted until those native destinations exist.
5. The original source is the React WebView/SQLite WASM product; the native redevelopment is Android Compose/SQLCipher. Security keys, password recovery and database files are **not interchangeable** across these runtimes.
